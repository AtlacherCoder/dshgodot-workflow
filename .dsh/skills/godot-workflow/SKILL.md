# Godot 工程开发工作流（AI 工作守则）

> 来源：本地插件 `dsh-godot-workflow`。**常驻核心**（五条铁律 + 流程骨架 + 崩溃级硬约束）已随系统提示
> 注入到每个会话；本技能是**完整版**，供需要流程细则、硬约束全表与模板时加载。
> 因此下面的动作是**默认动作**——**不要等用户提醒**"问清楚再动手""记得写决策日志"。
>
> 适用：本机的 Godot 4.6 工程（`/home/atlaslinux/ADD/` 下的四个工程）。
> 非 Godot 任务沿用第 1 节的流程部分，跳过第 2 节的 Godot 专属命令。
>
> ⚠️ 字节预算：全局 + 项目链总量不得超过 65536 字节，且**超预算时最宽泛的文件（就是本文件）先被丢弃**。
> 本文件要保持在 ~10KB 以内；往这里加内容前先 `wc -c` 看一眼。

## 0. 五条铁律

1. **先问后做** —— 凡是要"定夺"的，先变成带选项的问题；不要替用户决定观感、手感、范围。
2. **一轮一主题** —— 范围先收窄；顺手发现的真缺陷单独记一条，问过再动。
3. **看得见才算完** —— 测试绿 ≠ 做完。用户可见的改动必须有**真实窗口的截图 + 读数**。
4. **每轮一条决策 + 一个回退点** —— 没有回退件的改动不允许收口。
5. **红就说红** —— 未通过、未做、误判撤回，全部写进报告，不许粉饰。

## 0.5 用户看重什么（判断依据）

| 看重 | 具体表现 |
| --- | --- |
| 先问后做 | 定夺项必须给选项；不问就动手 = 返工 |
| 一处定义 | 同一规则出现第二份拷贝要提出来收掉；**"两个入口只改一个"是最大忌讳** |
| 眼见为实 | 要真实窗口的截图与数字读数，不信"套件绿了" |
| 可回退 | 每轮都要有能执行的回退件，且回退件自己要先自检 |
| 说真话 | 报红、报未做、撤回自己的误判；不要"看起来完成了" |
| 小步 | 扩大范围要先说理由并征得同意 |
| 报告形式 | 中文、要点、表格；读数给数字，别写散文 |

## 1. 每一轮的固定流程

### ① 摸底（不许凭记忆改）

- 先 `grep` / `read` 找到**真正被使用的那一份**文件。本工作区同一个关卡有多份拷贝
  （例：`shield_room` 有三份），改错拷贝 = 用户会说"没有改变的"。
- 先找**同类实现**（兄弟关卡、既有公共件），优先沿用既有风格，而不是新造一套。
- 记下三件事：**谁在管这件事**、**挂钩点在哪**、**有没有现成的信号/事件**。

### ② 提问（这一步不许省）

用 `ask_user_question`：每个问题 2–4 个选项，**第一个是推荐项并写清代价**。

- 只问**用户能判断的**：观感、手感、范围、要不要一起做、怎么验收。实现细节是自己的活。
- 一次问完（≤4 个），不要挤牙膏；用户答复后按答复执行，不要再反复确认。
- 用户中途追加的约束（例："别忘了把盾的碰撞体与形状一直同步"）= **硬验收项**，写进当轮清单并逐项核对。

### ③ 修改清单（要改的**内容**，不是要改的程序）

表格三列：`要改什么 | 改成什么 | 为什么`。

牵涉共用件/基类时，必须写清**受影响面**（"所有继承它的关卡"），而不是"我记得的那几关"。

### ④ 开工

- **一处定义**：发现同一规则的第二份拷贝 → 停下来提出来，问要不要一起收。
- 每改一处自问：**这条线接上了吗？**（模型改了 → 关卡调到了吗？组件改了 → 调用方接了吗？）
- 挪动实体/玩家要走它自己的入口函数（`place_player()` 之类）；直接写字段会被每帧覆盖。
- 像素相关的量（偏移、时长、尺寸）要给**具体数字**，并说明为什么是这个数。

### ⑤ 三层验证（缺一层不算完）

1. **单元/契约**：新增或改动的语义都要有套件钉住。
2. **接线**：走**真实入口**（按键、真实事件路径）断言"关卡/调用方真的接上了"。
3. **目视**：真实窗口跑一遍 → **读数表格 + 截图**存进 `docs/screenshots/`。
   - 起真实窗口**前**先 `godot_ping`：用户可能正在同一个窗口里玩，别抢他的会话、也别把他在玩的状态当成 bug。
   - 用完**必须**清理注入物（见 2.2）。

### ⑥ 收口

1. **决策日志两轨**：`docs/decisions.jsonl` + `docs/DECISIONS.md` 各写一条 →
   `python3 tools/sync_decisions.py verify` 必须通过（`phase` 只能用校验器允许的枚举值）。
2. **回退件** `docs/rollback/R-0xx/`：`revert.py`（`--check` 校验"每条规则恰好命中一次 + 撤完零残留"，
   不通过**绝不写文件**）或原文件副本 + `RESTORE.md`（含逐条 `cp` 命令）。
   回退要能**倒序链式**执行；后一轮改写了前一轮的文本时，旧脚本 `--check` 会红——这是安全网，如实记录。
3. **交接摘要**：更新计数（发现集文件数 / 自动跑套件数 / 决策条数）、写本轮条目、
   **把新踩的坑写进坑清单**（这是这套流程最值钱的部分）。
4. **报告四段**：`做了什么 / 验证读数 / 还红什么（含原因）/ 没做什么`。

## 2. Godot 环境硬约束（违反会崩、或静默出错）

1. **绝不用 bash/pwsh 起 Godot**：文件沙箱拦 `user://` 写入 → `signal 11` 崩溃，不是工程问题。
   用 `godot_run_headless`（无头跑套件/脚本）、`godot_run_project`（真实窗口）、`godot_command`（驱动运行中的实例）。
2. **真实窗口用完必须删掉注入的 autoload**：`autoload/mcp_interaction_server.gd`（+`.uid`），
   以及 `project.godot` 里那一行 `McpInteractionServer=`；并 `godot_stop_project` 收掉托管实例。
3. **工程本身不许有 autoload**：全局能力用静态类（`extends Object` + `static func`）。
   `--script` 模式下注册 autoload 会让 UI 层静默编译失败并级联拖垮整个场景。
4. **跑测试用可续跑的 worker**：`tools/run_tests_worker.gd`（账本 `docs/test-results.txt` 按"每套最后一次结果"
   去重续跑；想只跑几套就写 `docs/test-only.txt`）。单次工具调用约 130 秒上限，全套四分钟以上 → 反复调用即可。
5. **新增/替换任何 PNG 后必须跑 `tools/reimport_assets.gd`**：`--script` 模式不跑导入管线，
   漏跑会在用到那张图时报 `No loader found for resource`。
6. **`eval` 的四个坑**（都会让游戏进调试器断点 → 整个交互服务停摆，只能重启实例）：
   - 不要写带缩进的块（`while`/`for`/`if` 的换行体）→ 用 `if cond: return x` 单行形式，或干脆不写块；
   - 不要写错属性名/方法名（写之前先确认真有；模型字段 ≠ 关卡字段）；
   - `await` 会让返回值变 `null`（**副作用照常发生**）→ 把结果 `set_meta()` 存下、下一次 eval 再读；
     `result: null` 同时是"这次 eval 中途报错了"的信号；
   - 不要写 `var x := <未定型表达式>`（用显式类型或 `var x =`）。
7. **编辑器保存过 `.tscn` 之后**，Godot 会给每个节点加 `unique_id=…` →
   所有用**逐字文本锚**的回退脚本都可能失效，要重跑一遍 `--check`。
8. **`/tmp` 是每次 bash 调用全新的 tmpfs**：要留实验副本（例如验证回退脚本）就放工作区里，
   别放 `/tmp`；工程副本也别放进工程内部（引擎会把它的资源一起导入）。

## 3. 交活前自查清单

- [ ] 新语义有套件钉住，且断言走**真实入口**
- [ ] 改动落在共用件上 → 列出来并**跑过所有继承者**
- [ ] 真实窗口：有读数 + 截图；注入的 autoload 与实例**已清理**
- [ ] 真实验证前 `godot_ping` 过（确认窗口里没人在玩）
- [ ] 决策日志两轨一致（`sync_decisions.py verify` 通过）
- [ ] 回退件 `--check` 通过（或明确写"本轮没有回退件 + 为什么"）
- [ ] 交接摘要的计数 / 本轮条目 / 坑清单已更新
- [ ] 报告四段齐全，且如实列出仍红的套件与原因

## 4. 模板

### 提问

```
<问题>：<一句话背景>
- A: <推荐做法>（代价：…）(Recommended)
- B: <另一条路>（代价：…）
```

### 决策条目（两轨同写）

```
## R-0xx — <一句话主题>（<日期>）
- phase: <校验器允许的枚举，如 levels / ui / common / assets / verify>
- decision: <改了什么，含关键数值>
- rationale: <用户原话 / 为什么这么做>
- alternatives: <没选的路 + 为什么没选>
- evidence: <跑了哪些套件、各多少项、真实窗口读数>
- files: <清单>
- reversible: <回退件路径 + --check 结论；没有就写为什么>
```

### 回退脚本骨架

`--check` 只校验不写；每条规则**恰好命中一次**；撤完**零残留**（关键词不再出现）；
任何一条不满足就报错退出、**绝不部分写入**；写之前打印"每条规则做了什么"。

### 报告

```
## <主题>
<一到两句结论>
| 项目 | 数字/读数 |
- **验证**：套件名 + 项数 + 真实窗口读数
- **还红**：套件名 + 原因（是既存红灯还是本轮引入）
- **没做**：明确列出
```
