# Godot 工程开发工作流（常驻核心 · 默认动作）

> 适用：本机 Godot 4.6 工程（`/home/atlaslinux/ADD/`）。非 Godot 任务沿用流程部分。
> **完整版**：用 `skill` 工具加载 **`godot-workflow`**（铁律详解、流程细则、硬约束全表、四类模板）。

## 五条铁律

1. **先问后做** —— 要"定夺"的先变成带选项的问题；不替用户决定观感、手感、范围。
2. **一轮一主题** —— 范围先收窄；顺手发现的真缺陷单独记一条，问过再动。
3. **看得见才算完** —— 测试绿 ≠ 做完；用户可见改动必须有**真实窗口截图 + 读数**。
4. **每轮一条决策 + 一个回退点** —— 没有回退件的改动不允许收口。
5. **红就说红** —— 未通过、未做、误判撤回，全部写进报告。

用户中途追加的约束 = **硬验收项**。

## 固定流程

① **摸底**：先 `grep`/`read` 找到**真正被使用的那一份**（同关卡常有多份拷贝，改错 = "没有改变的"）；先找同类实现沿用风格；记下"谁在管、挂钩点、有无现成信号"。
② **提问**：`ask_user_question`，每题 2–4 项、**首项推荐并写清代价**；只问用户能判断的（观感/手感/范围/验收）；一次问完（≤4），答复后不再反复确认。
③ **修改清单**：`要改什么 | 改成什么 | 为什么`；涉及共用件必须写清**受影响面**。
④ **开工**：发现同一规则的第二份拷贝 → 停下来问要不要一起收；每改一处自问"这条线接上了吗"；像素量给**具体数字**并说明理由。
⑤ **三层验证**（缺一层不算完）：契约 → 接线（走**真实入口**）→ 目视（真实窗口读数 + 截图存 `docs/screenshots/`）。起窗口**前先 `godot_ping`**。
⑥ **收口**：决策日志两轨 → `python3 tools/sync_decisions.py verify` 必须通过；回退件 `docs/rollback/R-0xx/`（`--check` 通过才写文件）；更新交接摘要与坑清单；报告四段。

## Godot 崩溃级硬约束

1. **绝不用 bash/pwsh 起 Godot**（沙箱拦 `user://` → `signal 11`，**不是工程问题**）。用 `godot_run_headless` / `godot_run_project` / `godot_command`。
2. **真实窗口用完必须删掉注入的 autoload**（`autoload/mcp_interaction_server.gd` + `.uid` + `project.godot` 那一行）并 `godot_stop_project`。
3. **工程本身不许有 autoload** —— 全局能力用静态类。
4. **`eval` 四坑**：不写缩进块；不写错属性/方法名；`await` 使返回值变 `null`（副作用照常，用 `set_meta()` 转存）；不写 `var x := <未定型>`。踩中会把游戏送进断点、交互服务停摆。
5. **新增/替换 PNG 后必须跑 `tools/reimport_assets.gd`**，否则 `No loader found for resource`。
6. **`/tmp` 每次调用全新** —— 实验副本放工作区。

## 报告

中文、要点、表格；读数给数字。四段：`做了什么 / 验证读数 / 还红什么（含原因）/ 没做什么`。
